执行 glass-researcher 日度四段式 pipeline。顺序不可颠倒：结算 → 进化 → 新研判 → 播报。

第一段【结算】派遣 glass-researcher（告知其当前规格版本号，从 genesis/registry.json 读取）执行结算：取台账待结算行目标交易日的行情数据，结算该信号行，重算 performance.json。（若其规格尚为 v1 单段式日结，则让其执行完整日结并跳到第三段说明）补充授权【派遣方明示纠错】：若台账存在「状态=数据缺失 且其目标交易日行情现已可得（例如盘中误判缺失、日K现已发布）」的行，你作为派遣方明示授权 glass-researcher 按规格的如实纠错条款重新结算该行（备注注明纠错原因），纠错结果如实进入指标——包括让指标变差的修正。

第二段【进化】日度进化轮。铁律：真正的进化=结果距标准持续收窄（win_rate→0.85+、entry_rate→0.80+、violation_count→0），变更不是进化，差距恶化一律回滚。步骤：读结算后的 performance.json 与 journal，计算三项差距，与最近一份进化日志对比收窄/停滞/恶化；归因后在五维度选其一立项（数据缺失多→数据源；入场率低→参数；连续亏损→参数；产出缺陷→提示词；能力缺口→技能/MCP）；立项走完整协议（architect 起草→evaluator 裁决→PASS 才部署+登记 registry，FAIL 丢弃）；差距收窄中→不动仅记录；降级警示（consecutive_losses>=3 或近10笔胜率<0.7）→强制立项；小样本护栏：entered<20 时只允许低风险进化（数据源/提示词修复），禁调核心策略参数。产出进化日志 genesis/reports/daily-evolve-当日日期.md，更新 registry 的 last_eval_at。

第三段【研判】派遣 glass-researcher（若第二段已部署新版本，用新版本，并告知新版本号）产出研判：基于最近已收盘交易日的数据，产出下一交易日研判日报（按其规格约定的日期命名）、台账追加新信号行（备注记录规格版本号）、重算指标，汇报明日信号三要素。若目标日信号已存在（幂等护栏），如实汇报不重复追加。研判日报落盘后，**立即写报告通知文件 glass/push/report-YYYYMMDD.md**（YYYYMMDD=研判目标交易日日期，用 write 工具创建）。文件格式（UTF-8）：第一行标题「【RSI】FG研判 YYYY-MM-DD」（目标交易日），空一行，正文四行（markdown，全部取自当次研判日报，禁止编造）：方向：多/空/中性 合约；区间：S1/S2/R1/R2（核心区间）；入场：触发价/止损价/目标价（仓位，盈亏比）或观望+一词理由；依据：一句话。

第四段【播报】把当日复盘简报写入文件 glass/push/brief-YYYYMMDD.md（当日日期，用 write 工具创建，路径不存在会自动建目录）。文件格式（UTF-8）：第一行是标题「【RSI】FG复盘 YYYY-MM-DD」（【RSI】为固定来源标记，不带数值），空一行，然后正文四行（markdown）：结算：…；明日：…；指标：胜率 W/E | 入场率 E/T | 违规 V | 连亏 N；进化：动/不动+一句话理由。数值一律取自台账与 performance.json 实际数据，禁止编造。【注意】推送由 pipeline 外层 PowerShell 脚本执行（它会读你写的文件并调用钉钉），你**不要**在会话内调用推送命令、不要写临时 PowerShell 脚本传中文参数（编码坑）。简报文件写入成功即本段完成。

硬边界：无头自动运行；禁止修改 genesis/goals.md 与 genesis/eval/**（L0 冻结）；不确定时只记录不行动；FAIL 照实记录。
