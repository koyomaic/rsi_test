# 玻璃研究员进化路线图（框架驱动模式）

> 范式：先建**价格研判框架**（方法论×品种），拆解为 skill 与数据组件，组件在框架内持续进化。
> 差距归因落到框架的**具体因子/skill**，不做无结构的随机游走改进。
> 本文档为 L1 策略层滚动计划，每阶段完成后复盘并重写（滚动制定）。

---

## 一、范式声明

- **框架 = 套路**：所有进化动作必须可定位到框架的某个组件（因子/skill/数据/参数）
- **差距 = 动力**：结果指标（胜率/入场率/方向准确率）的差距归因映射到组件
- **框架本身也是进化对象，一切服务于目标**：

### 框架进化机制

**触发器**（满足其一即启动框架评审）：
1. 常规评审：每 10 笔前瞻样本或月度（慢节奏——结构不宜频繁动）
2. 归因升级：skill 级迭代**连续 2 轮无法收窄差距** → 判定非组件问题而是结构问题 → 强制框架评审
3. 用户指令

**可进化面**：因子增删、权重调整、判定规则、层级结构

**裁决标准**（与其他进化完全一致）：
- 变更必须挂接明确的结果差距（"这个变更收窄哪个指标、预期多少"）
- 走完整协议：architect 起草 → evaluator 裁决 → PASS 部署 → framework.md 版本化（registry 登记）

**防框架自嗨（Goodhart 约束）**：
- 无差距归因的框架变更不予立项（不为精致而精致）
- 复杂度预算：因子数量与文档长度有上限——复杂度本身是过拟合源，新增因子必须以剔除或证明增益为前提
- 框架变更后 G5/G6/胜率未收窄 → 回滚框架版本（同变体回滚机制）

## 二、玻璃（FG）研判框架 v1.0（三层结构）

```
┌─ 第一层：方向（基本面因子合成，加权评分 → 多/空/中性）
│    供给因子（~25%）：日熔量趋势、冷修/点火事件
│    需求因子（~25%）：地产竣工与政策、深加工订单/沙河走货
│    库存因子（~20%）：厂家库存天数趋势（短期供需最直接验证）
│    成本因子（~15%）：纯碱(SA)+燃料(天然气)→生产利润→供给弹性
│    基差因子（~10%）：基差率（现货-期货）/现货价
│    资金因子（确认作用）：郑商所会员持仓排名变化（主力净持仓）
│    事件叠加（方向性）：地产政策、环保限产、宏观 risk-off
├─ 第二层：区间（技术结构，现有 ATR/支撑压力系统保留）
└─ 第三层：入场执行（现有触发/止损/目标参数系统保留）
```

**现有 v4 只覆盖第二、三层**；第一层方向判断目前仅"两三根 K 线+板块联动"——框架升级的主战场。

## 三、Skill 拆解（进化单元）

| Skill | 职责 | 依赖数据 | 初始状态 |
|---|---|---|---|
| `skill-supply` | 日熔量趋势+冷修事件解读 | 新闻 | 新建 |
| `skill-inventory` | 库存天数趋势与背离判断 | 新闻兜底 | 新建（高优先） |
| `skill-cost` | 成本利润计算（SA+燃料） | MCP+新浪 | 新建（数据全可得） |
| `skill-basis` | 基差率监控与信号 | 现货源 | 新建 |
| `skill-positioning` | 会员持仓净变化 | 郑商所 | 新建（数据免费） |
| `skill-tech` | 区间/ATR（现有） | 日K | ✅ 已有（v1~v4） |
| `skill-macro-event` | 事件雷达与权重叠加 | 新闻 | 新建（后置） |

每个 skill = 独立进化单元，有自己的输入→计算→输出定义。进化轮归因：方向错 → 定位到哪个因子评分错 → 迭代哪个 skill。

## 四、指标升级（配合框架）

performance.json 新增（在现有 G1~G4 基础上）：

- **G5 方向准确率**：因子合成方向 vs 实际走势（预判日涨跌方向），目标 ≥60%（初期）
- **G6 区间准确率**：预判核心区间覆盖率（实际高低点落在核心区间的比例），目标 ≥70%

（G5/G6 与胜率 G2 独立——方向对但没入场≠错误研判；触发后亏损才计入胜率）

## 五、实施阶段（滚动，每阶段完成→复盘→重写本计划）

### 阶段 F1：框架定稿与数据盘点（1~2 天）

- [ ] 研究主流期货分析方法（供需平衡表/库存-价格/成本利润/基差结构/持仓资金），结合玻璃品种特性
- [ ] 产出 `glass/framework.md` 研判框架 v1.0（因子树+评分规则+数据映射，由 genesis 部署、researcher 按版本使用不自行修改）
- [ ] 数据源排查：沙河现货免费源、郑商所持仓页面抓取验证、新闻兜底源清单
- 验收：框架文档落地（含每个因子的数据来源、计算式、方向判定规则）+ 数据矩阵更新

### 阶段 F2：核心 Skill 实装（2~3 天）

- [ ] 实装 4 个数据全可得的 skill：cost（SA+天然气）、positioning（郑商所）、basis（现货源）、inventory（新闻兜底）
- [ ] glass-researcher 规格升级 v5：研判流程 B 增加因子评分节（读取框架→逐因子评分→合成方向→技术区间→执行参数）
- 验收：日报出现因子评分表；v5 走完整自进化协议部署

### 阶段 F3：框架整合与指标上线（1~2 天）

- [ ] G5/G6 指标进 performance.json 与进化轮
- [ ] 评估集新增方向/区间准确率任务
- 验收：连续 2 个交易日产出完整三层研判，G5/G6 有计量

### 阶段 F4：Skill 进化循环（持续）

- 每日进化轮归因升级：差距 → 定位因子 → 迭代对应 skill（参数/数据/逻辑）
- 每 10 笔前瞻样本或月度：框架评审（因子增删/权重调整，走协议）
- 回测加速器：历史回放验证因子权重（回测样本独立统计，严禁混入正式指标）

## 六、防 gaming 红线（框架模式特有）

1. 回测样本与前瞻样本**严格分离**（回测只做参数/权重选优，不进 win_rate）
2. 框架文档由 genesis 版本化管理，researcher 只读使用（台账红线同理：不回改、不美化）
3. 因子权重调整必须走自进化协议（architect→evaluator→PASS 部署），不允许"今天拍脑袋改权重"
