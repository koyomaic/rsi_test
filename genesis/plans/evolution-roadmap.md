## 一、不变的进化原则

1. **框架 = 套路**：所有变更定位到决策、Skill、数据、执行、记忆或呈现层，拒绝随机游走。
2. **差距 = 动力**：变更必须挂接结果差距与归因组件；没有证据的“框架美化”不立项。
3. **三层验证**：静态审计证明文本改对，运行时测试证明流程可用，前瞻结果证明能力改善；三者不得互相冒充。
4. **双轨样本**：回测只用于提出/筛选假设，正式指标只认前瞻样本，严禁混账。
5. **可回滚**：框架、Skill、agent 均版本化；变更范围必须恰为声明，恶化如实回滚。
6. **复杂度预算**：新因子须证明增量价值或替代旧因子，不为显得先进而扩张。

## 三、框架 v1.0 的最终结构（替代上一版设想）

```text
第一层：方向先验
  库存30% + 供给25% + 需求25% + 基差/月差20%
  → 数据覆盖率C、方向分S、方向与基础置信度

独立修正器
  成本利润：产业下沿与供给响应，不把亏损直接当反转
  会员持仓：确认/背离，只调置信度，不独立翻方向
  事件：通过基本面数据兑现后再计分

第二层：技术区间
  现有ATR5、近5日高低点、整数关口、S1/S2/R1/R2

第三层：入场执行
  现有触发/止损/目标、入场可达性、不扛单与每日最多一笔
```

关键数据纪律：

- 缺失或 stale = null，不是中性0；覆盖率不足不得被持仓信号补齐。
- 全国元/㎡现货只看趋势；绝对基差必须使用同区域、品规、税口径的元/吨数据。
- 周度产业数据保留原始 as_of，不能日度化；同源转载不算独立样本。
- MCP 实测不覆盖现用FG/SA主数据，只保留能源与宏观辅助。

### F2：核心 Skill 实装——当前待启动（2～3个自然日）

详细任务书：`genesis/plans/f2-skill-implementation.md`。

目标：把框架变成可重复执行、可独立复算的日度流程，而不是只增加文档。

最小垂直切片：

```text
Skill卡与数据契约
→ 四个方向因子+成本/持仓修正器
→ direction-composer
→ 至少2个历史日干跑（不碰正式台账）
→ glass-researcher v5变体
→ evaluator静态/算术/干跑/反gaming全PASS
→ v5 probation部署与registry追加
```

七道验收门槛：

1. Skill输入/输出/缺失规则完整；
2. C/S/方向/置信度独立复算一致率100%；
3. 所有评分数据含as_of、单位、口径、来源、新鲜度；
4. 未知=null注入全部被正确拦截；
5. v4的L0、结算、ATR、两阶段、幂等零漂移；
6. v5未经PASS不得部署，部署后可回滚v4；
7. 不宣称G2/G3/G5/G6已经改善。

F2明确不做：调权重、调ATR、把回测写入正式台账、为凑Skill数量扩张组件、未经批准修改永久评估集。

### F3：真实接入与指标上线——满足入口条件后制定详细计划

入口条件：F2七项验收全部通过，v5已合规部署。

拟验收：

1. 连续2个真实交易日保留完整因子表和合成结果；
2. G5/G6记录可独立重放，公式与framework v1一致；
3. G5同时报告有效日数、非中性日数、正确数、准确率、direction_coverage；
4. G6同时报告有效样本数、区间覆盖率、完整容纳率；
5. 样本<20只作诊断，不作结果性进化结论；
6. 永久评估集若需新增任务，必须单独取得用户批准。

初期参考目标：G5方向准确率≥60%、G6区间覆盖率≥70%，同时要求G2/G3/G4不恶化。目标是否现实由样本检验，不通过降低口径制造达标。

### F4：Skill与框架的持续进化——F3后启动

- 快回路（日度）：结算、数据异常与执行层差距记录，不等于天天改参数。
- 中回路（样本批）：方向错误定位到具体因子/Skill，做契约内优化。
- 慢回路（框架评审）：每10笔有效前瞻样本或月度；同一Skill两轮无法收窄差距时强制结构评审。
- 失败资产化：典型误判→失败档案→回归判例，考察同类错误复发率，而非案例库大小。

1. F2七道验收全部完成；

5. F3获得首批真实G5/G6样本。

每次评审必须回答：上一阶段承诺了什么、外部证据是什么、哪些目标未达成、下一阶段为什么值得做、什么情况下应停止或回滚。
