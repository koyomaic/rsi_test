# 智能体自进化纲领（Evolution Manifesto）

> 一版从大模型与软件工程双视角出发的完整进化思路。
> 定位：本纲领是方法论宪法，回答"进化是什么、靠什么、怎么避免走歪"三个问题。
> 与 `evolution-roadmap.md`（滚动实施计划）配套使用：纲领定原则，计划定路径。

---

## 〇、总纲：三条第一性原理

1. **进化的本质是知识管理**。智能体种群不是"一群会聊天的程序"，而是一个**知识生产系统**：把外部数据转化为研判方法，把研判方法转化为可复用技能，把技能转化为可验证结果。进化的每一步都应是知识的积累或结构化，而非文本的随机改动。

2. **基因型 ≠ 表现型**。文本资产（prompt/框架/skill）是基因型，行为输出（研判质量/交易结果）是表现型。**基因型改动是否改善表现型是概率性的**（LLM 对指令的理解存在解释空间，不像代码修改是确定性的）。因此：每一次文本变更都**必须**经行为评估验证，"文本看起来更好了"不构成任何进化证据。

3. **进化必须服从工程纪律**。没有版本化就没有回滚，没有评估就没有方向，没有复杂度预算就没有可持续。这三条是硬约束，不是风格偏好。

## 一、双视角洞察

### A. 大模型视角（五条，每条对应一条设计决策）

| # | LLM 特性 | 对进化的含义 | 设计决策 |
|---|---|---|---|
| A1 | **幻觉不是 bug 是特性**：编造数据是模型本能，不是异常 | 不能指望"教它别编"，要机械约束 | 数据必须带来源标注；台账不可回改（已实现 L0） |
| A2 | **概率行为**：同输入不同输出，单次评估噪声大 | 一次跑赢/跑输不能裁决变体 | 评估必须多任务+统计口径；PASS 看分布不看单点 |
| A3 | **自我评估与生成同源**：模型给自己的作业打分必然偏高 | 自评分永不做选择依据 | 裁判独立（evaluator 分离）+ 只认外部命令输出（已实现） |
| A4 | **prompt 进化有天花板**：提醒能改变注意力，不能创造方法 | 能力增长必须靠技能封装与数据获取 | 知识靠数据源进化，技能靠 skill 进化——prompt 只做调度层 |
| A5 | **模型可替换性**：同一文本在不同模型上表现不同 | 模型切换 = 物种迁移，需要重新验证 | 进化产物（框架/skill/评估集）与底层模型解耦，换模型不换知识 |

### B. 软件工程视角（五条，映射到具体机制）

| # | 工程智慧 | 映射 |
|---|---|---|
| B1 | **Lehman 熵增定律**：系统不维护就退化 | 智能体不进化不是稳定而是退化——但"维护"要防的是退化，不是求变 |
| B2 | **测试金字塔**：单元→集成→系统→验收，成本递增价值递增 | 因子计算（单元）→ skill 组合（集成）→ 日结产物（系统）→ 胜率/方向率（验收）——**结果指标是 UAT，是进化的最终裁判** |
| B3 | **回归测试**：每次变更重跑历史集，防旧能力退化 | 灾难性遗忘防线：评估集保留历史判例（失败案例是回归测试的最高价值成员） |
| B4 | **契约式设计**：组件有输入/输出/前置后置条件契约 | skill 有契约（数据需求→计算→输出格式），契约稳定则内部实现可自由进化 |
| B5 | **事件溯源**：事件流 + 物化视图 | journal.md = 事件流，performance.json = 物化视图（幂等重算）——已实现，允许任意时点重放审计 |

## 二、进化架构

### 2.1 分层模型（关注点分离，每层独立进化/测试/回滚）

```
┌─ 决策层：研判框架（方法论结构——因子树/权重/判定规则）
│      慢节奏进化（每 10 笔样本或月度评审）
├─ 方法层：skill 技能（因子计算/研判模板——契约化组件）
│      中节奏进化（按样本批归因）
├─ 数据层：数据源（行情/产业/宏观）
│      按需进化（缺口驱动）
├─ 执行层：参数（触发/止损/目标距离）
│      快节奏进化（日度差距归因）
├─ 记忆层：经验（案例库/判例回放/失败档案）
│      持续积累（只增不改）
└─ 呈现层：输出（日报/简报/通知）
      按需进化（用户反馈驱动）
```

依赖方向自上而下单向：决策依赖方法契约，方法依赖数据，执行依赖决策输出。**依赖倒置**：框架引用 skill 的接口而非实现——替换 skill 实现不需要改框架。

### 2.2 基因型与表现型的对照表

| 基因型（文本资产） | 表现型（行为证据） |
|---|---|
| 框架文档/skill 契约 | 因子评分与实际走势的一致性（G5/G6） |
| 系统提示（调度指令） | 日结产物的格式与纪律遵守率 |
| 执行参数 | 触发率/胜率（G2/G3） |
| 案例库 | 同类错误复发率（经验是否真正起作用） |

进化的完整定义：**基因型变更 + 表现型验证 + 知识保留**——三者缺一即不算进化。

## 三、三回路节奏（拒绝一刀切）

不同层有不同的时间常数，**节奏与层的抽象级别成反比**：

```
快回路（日度）：结算 → 差距 → 执行参数微调
  └ 唯一允许天天动的层；小样本护栏在此层生效
中回路（样本批）：skill 归因与优化
  └ 每 10 笔前瞻样本或触发警示时；契约不变，实现可换
慢回路（月度/框架评审）：框架结构进化
  └ 因子增删/权重调整；触发条件：skill 级迭代连续 2 轮无法收窄差距
```

**判定"慢悠悠"的正确标尺**：不是"几天没改参数"，而是**三回路各自是否按自己的节奏在转**。快回路空转（0 样本多日）才需要人工加速（回测），而不是逼慢回路频繁动。

## 四、评估体系

### 4.1 四层测试金字塔

| 层 | 对象 | 方法 | 示例 |
|---|---|---|---|
| 单元 | 单个 skill 计算 | 已知输入 → 断言输出 | 给定 14 日收盘序列，断言 RSI/成本利润值 |
| 集成 | skill 组合 | 固定数据 → 流程产物检查 | 日结六节/15 列台账/指标 JSON 合法 |
| 系统 | 端到端行为 | 真实派遣 → 产物与行为审计 | v2 两阶段冒烟、B2 自愈注入 |
| 验收 | 结果指标 | 前瞻样本累计 | G2 胜率 / G3 入场率 / G5 方向率 / G6 区间率 |

### 4.2 双轨样本（铁律）

- **前瞻轨**（唯一进 win_rate 的样本）：真实时间线、真实结算，按日积累
- **回测轨**（加速器）：历史回放用于参数/权重选优——**严禁混入前瞻指标**；回测台账独立文件独立统计

### 4.3 裁判独立性（已实现，保留为永久约束）

- evaluator 与被测对象分离部署；只认命令输出
- 评估集修改需用户批准（防被测对象改写考题）
- evaluator 必须披露自身工具缺陷（已出现两次真实案例——这是裁判可信度的来源）

## 五、知识沉淀（LLM 特有的进化杠杆）

1. **失败档案馆**：每次错误研判/失败任务必须解剖归档——归因、当时数据、错误类型。失败判例自动进入回归评估集（B3 的落地）。
2. **案例库**：成功与失败的双向判例，标注"适用条件"。经验资产化的检验标准：**同类错误复发率下降**，而非"库变大了"。
3. **判例回放**：重大失误（如 11-17 超卖反转日看空）构造为独立评估任务——将来任何框架变更都必须在这个判例上不重演错误。
4. **知识-技能-能力三分**：知识（数据源）/技能（skill）/能力（决策涌现）——能力不可直接编辑，只能通过前两者的进化和经验的积累间接提升。这是"匠心"的真正着力点。

## 六、进化控制论（防止走歪的操作系统）

| 机制 | 规则 |
|---|---|
| **定向变异** | 每次立项必须挂接：哪个结果差距 → 归因到哪个层/组件 → 预期收窄多少 |
| **探索预算** | 变异分两类：利用性（80%，归因明确）与探索性（20%，框架允许的新尝试）——防止完全丧失探索能力 |
| **复杂度守恒** | 每增加一个组件/因子，必须附带一个简化或淘汰动作；复杂度本身是过拟合源 |
| **能力边界显式化** | 框架文档必须写明"本框架不做什么"（如不预测政策时点、不使用未授权数据）——防越界膨胀 |
| **变更范围审计** | 每次变体 diff 必须恰为声明范围（已实战：v3/v4 裁决） |
| **模型无关** | 进化产物不绑定特定模型；模型切换视为环境变化而非进化 |

## 八、落地顺序（在现有 F1 之后）

1. F1 框架定稿（决策层）→ F2 skill 实装（方法层）→ F3 G5/G6 上线（验收层补全）
2. 补建**失败档案馆**（glass/failures/）：解剖 11-17 与后续每次失败，入回归集
3. 引入**中回路**：每 10 笔前瞻样本触发 skill 归因评审
4. 引入**慢回路**：框架月度评审（首次在 G5/G6 有 20 样本后）
5. 探索预算与复杂度守恒写入框架评审议程

## 结语（本纲领的自我约束）

本纲领本身也是进化对象——但修改它需要比框架更慎重的理由：**纲领的修改必须证明是既有原则无法解释的新情况，而非措辞偏好**。进化体系最大的敌人不是不变，而是为了显得在进化而进化。
