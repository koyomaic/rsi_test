# F2：玻璃研判核心 Skill 实装计划（滚动版 v1）

> 前置：F1 框架 v1.0 已通过两轮静态裁决，首轮 FAIL 与修订记录均保留；正式框架以 `glass/framework.md` 的 probation 版本为准。
> 阶段性质：方法层实装，不调执行参数，不承诺结果指标改善。
> 计划期限：2～3 个自然日；完成后按验收证据复盘并重写后续计划。

## 一、阶段目标

把框架 v1.0 从“只读方法契约”变成研究员可重复执行的日度流程：

```text
读取框架与 Skill 卡
→ 按统一数据契约取数
→ 四因子评分
→ 独立计算 C / S / 方向 / 基础置信度
→ 成本与持仓修正
→ 技术与执行层沿用现有规格
→ 日报输出可复核的因子评分表
```

最终交易目标不变：G2/G3/G4 不恶化，并为 F3 的 G5/G6 计量提供结构化输入。F2 的成功定义是**计算一致、数据可追溯、流程可回归**，不是胜率上涨。

## 二、实施范围

### 2.1 本阶段实装

| 组件 | 产物/职责 | 验收重点 |
|---|---|---|
| `skill-data-contract` | 统一 value/unit/spec/as_of/source/freshness 字段 | 缺字段不得评分 |
| `skill-inventory` | 连续去库/累库、同比与库存结构标签 | 单周不冒充趋势；同源不冒充独立 |
| `skill-supply` | 日熔量趋势与冷修/复产净方向 | 未知=null，不进入分母 |
| `skill-demand` | 订单与地产需求的边际趋势 | 单期水平不冒充趋势 |
| `skill-basis` | 现货/基差/月差三组件评分 | 单位一致；区间不取中点；组件<2=null |
| `skill-cost` | 三路线利润与供给响应状态 | 只作修正器，不直接做多 |
| `skill-positioning` | 前20净持仓变化与价仓背离 | 合约范围明确；覆盖不足锁低 |
| `skill-direction-composer` | C、S、方向和置信度合成 | 独立复算100%一致 |
| `skill-tech` | 现有 ATR 与 S/R | 本阶段不变 |

Skill 卡的正式存放建议为 `glass/skills/`，保证 glass-researcher 在现有只读权限内可使用。它们是受版本控制的方法资产，不是让研究员现场自行改写的提示词。

### 2.2 明确不做

1. 不调整库存/供给/需求/基差的 30/25/25/20 权重；
2. 不调整 0.30 方向阈值、0.60 覆盖门槛；
3. 不调整 ATR 触发/止损/目标参数；
4. 不把回测结果写入正式 journal 或 performance；
5. 不在 F2 修改 `genesis/eval/**`；若需新增永久评估任务，先单独向用户申请；
6. 不为了“Skill 数量”拆分更多组件，先做通一个完整垂直切片。

## 三、执行步骤

### F2-A：Skill 卡与样例（genesis 起草）

- 每个 Skill 写清：输入契约、取数源、计算步骤、评分映射、缺失分支、输出字段、失败判例；
- 使用**合成样例**做计算测试，必须标注 synthetic，不能写成真实行情；
- 使用研究报告中已有的历史事实只作来源回归，不产生新交易信号。

### F2-B：研究员 v5 变体（architect 起草）

仅允许声明以下变化：

1. 自述版本 v4→v5；
2. B1 增加框架产业数据取数；
3. B4 前增加因子评分与方向合成；
4. 日报增加因子评分表和合成结果；
5. 必要的玻璃公开数据 URL 指引。

必须逐字保留：L0 硬边界、结算规则、15列台账、performance 现有字段口径、ATR 参数、两阶段流程、幂等护栏和播报接口。若 v5 需要改变其中任何一项，必须重新单独立项，不能夹带。

### F2-C：独立评估（evaluator）

至少四类测试：

1. **静态 diff**：实际变更恰为声明范围，无 L0/参数漂移；
2. **单元算术**：独立复算 C/S、缺失退出、区间基差、置信度截断；
3. **历史干跑**：选择至少 2 个已有完整行情的历史日，仅写 `glass/research/f2-dryrun/`，不追加台账；检查数据契约和来源；
4. **反 Gaming 注入**：单期需求、未知供给、元/㎡现货、交叉区间、全中性预测，均须走正确分支。

静态与干跑全部 PASS 才可部署 v5 为 probation；任何真实结算或台账变更不在干跑授权内。

## 四、阶段验收门槛

| # | 验收项 | 通过标准 |
|---|---|---|
| F2-1 | Skill 契约覆盖 | 四个方向因子+成本/持仓修正器+合成器均有输入/输出/缺失规则 |
| F2-2 | 计算一致性 | evaluator 对干跑因子表独立复算，C/S/方向/置信度一致率100% |
| F2-3 | 数据可追溯 | 所有进入评分的数据含as_of、单位、口径、来源和新鲜度 |
| F2-4 | 缺失诚信 | 未知/null不进入分子分母，未知=0的注入全部失败并被拦截 |
| F2-5 | 边界保持 | v4的L0、结算、ATR、两阶段、幂等规则零漂移 |
| F2-6 | 部署纪律 | evaluator报告PASS、registry追加、v5=probation、可回滚v4 |
| F2-7 | 诚实性 | 报告不宣称G2/G3/G5/G6改善；只声明流程实装完成 |

## 五、进入 F3 的条件

F2 全部验收后，F3 才启动：

1. 在连续 2 个真实交易日的日报中保留因子表；
2. 为历史方向与区间结算建立独立、可重放的记录；
3. 设计 G5/G6 的存储字段和幂等重算方案；
4. 永久评估集若需变更，先向用户说明改什么、为什么并取得批准；
5. 样本不足20时只披露，不作“进化有效”结论。

## 六、失败与回滚

- 数据链无法支撑 C≥0.60：如实输出中性/低置信，不为凑覆盖而降口径；
- 因子表无法独立复算：v5 不部署或回滚 v4；
- 为接入框架而改动结算/ATR：视为越界，FAIL；
- 日报变完整但方向样本无可验证改善：只能判定“过程资产增加”，不能判定“结果性进化”。
